# Christiano Tadeu Trucks

Crie um website comercial completo, sofisticado, responsivo e preparado para evolução para a marca pessoal:

CHRISTIANO TADEU

CAMINHÕES VOLKSWAGEN

Assinatura da marca:

“O caminhão certo para sua operação.”

O projeto deve ser desenvolvido como uma aplicação web profissional, moderna e portátil, utilizando seu repertório de UX, UI, arquitetura de informação, conversão comercial e desenvolvimento frontend para melhorar a solução.

Antes de implementar, analise os arquivos anexados, especialmente o Manual Definitivo de Identidade e as duas versões da logomarca. Use o manual como fonte principal para posicionamento, personalidade, identidade visual, cores, linguagem e aplicação da marca.

Use sua experiência para aperfeiçoar a estrutura, navegação, usabilidade e conversão, mas não altere as decisões fundamentais de posicionamento, identidade e público descritas neste prompt e no manual.

1. CONTEXTO DO NEGÓCIO

Christiano Tadeu é um profissional experiente em venda consultiva de caminhões Volkswagen.

Ele trabalha principalmente de maneira ativa:

- visitando clientes;

- prospectando empresas;

- mantendo relacionamentos comerciais;

- analisando necessidades de transporte;

- apresentando caminhões e configurações;

- estruturando propostas;

- acompanhando negociações;

- auxiliando clientes em processos de financiamento;

- realizando acompanhamento até a entrega e o pós-venda.

Seu principal canal comercial é o WhatsApp.

A maioria de seus clientes é formada por:

- proprietários de transportadoras;

- empresários;

- gestores de frota;

- transportadores autônomos;

- produtores e empresas ligadas ao agronegócio;

- empresas de distribuição;

- empresas de construção e materiais;

- operadores logísticos;

- profissionais que dependem do caminhão para gerar receita.

A decisão de compra não é apenas emocional ou baseada em aparência. Ela envolve:

- tipo de carga;

- rota;

- capacidade;

- aplicação;

- implemento;

- consumo;

- produtividade;

- manutenção;

- disponibilidade;

- prazo;

- entrada;

- financiamento;

- impacto no caixa;

- custo de manter uma frota envelhecida;

- retorno esperado do veículo.

O site deve refletir essa realidade.

O Christiano não deve ser apresentado apenas como “um vendedor que anuncia caminhões”. Ele deve ser percebido como um especialista que entende a operação do cliente e ajuda a escolher o veículo adequado.

Posicionamento central:

“Christiano Tadeu ajuda empresas e transportadores a escolher e adquirir o caminhão Volkswagen mais adequado para sua operação, oferecendo clareza, atendimento próximo e acompanhamento durante todo o processo.”

Promessa da marca:

“Clareza para escolher, segurança para negociar e acompanhamento para colocar o caminhão certo em operação.”

Percepção que o site deve construir:

“Christiano não quer simplesmente vender o caminhão disponível. Ele quer entender minha necessidade e me ajudar a fazer uma compra adequada.”

6. PREPARAÇÃO PARA SUPABASE

Não é necessário conectar o Supabase nesta primeira implementação, mas toda a arquitetura deve estar preparada para isso.

Criar uma camada de acesso a dados desacoplada da interface.

Organização sugerida:

src/

components/

pages/

layouts/

features/

services/

data/

hooks/

types/

lib/

config/

assets/

Criar interfaces TypeScript para as entidades futuras:

- Lead;

- Customer;

- Company;

- Vehicle;

- TruckFamily;

- InventoryItem;

- FinancingOpportunity;

- CaseStudy;

- Testimonial;

- ContentPost;

- ContactInteraction;

- FollowUpTask;

- SiteSettings.

Nesta primeira versão, utilizar dados simulados em arquivos organizados dentro de src/data.

Não espalhar informações fictícias diretamente pelos componentes.

Criar uma interface de repositório ou serviço que permita substituir os dados simulados por consultas ao Supabase posteriormente.

Exemplo conceitual:

- leadRepository;

- inventoryRepository;

- caseStudyRepository;

- contentRepository;

- settingsRepository.

Preparar um arquivo:

docs/SUPABASE-MIGRATION.md

Esse documento deve explicar:

- quais entidades foram previstas;

- quais dados atualmente são simulados;

- quais tabelas deverão ser criadas;

- quais componentes dependerão do banco;

- como substituir os repositórios locais por Supabase;

- quais políticas de Row Level Security deverão ser consideradas;

- quais dados devem permanecer públicos e privados.

Também criar uma proposta inicial de banco em:

supabase/migrations/0001_initial_schema.sql

O SQL pode ficar preparado, sem ser executado.

Prever tabelas iniciais como:

- leads;

- vehicles;

- inventory_items;

- case_studies;

- testimonials;

- content_posts;

- contact_interactions;

- follow_up_tasks;

- site_settings.

Aplicar UUID, timestamps, status e campos de auditoria onde fizer sentido.

Não criar no frontend qualquer acesso com chave de serviço do Supabase.
